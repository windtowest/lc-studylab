# 检索增强代码学习 Agent：总体进度、答辩材料与记录总控

> 配套文档：[`design.md`](design.md)｜[`task.md`](task.md)  
> 用途：本文件是项目唯一的阶段总览与完成记录入口。每完成一项开发、实验、数据构建或 PPT 更新，都在对应任务下补充记录；后续制作开题、中期和最终答辩 PPT 时，直接从本文件提取已验证内容。  
> 当前技术主线：在本人实现的 LC-StudyLab 学习与研究 Agent 系统上，接入以**实验室 Java 后端仓库为主**的多粒度代码检索能力；前端小程序作为交互入口；研发文档 RAG 作为补充证据源。

## 1. 一页总览

```text
既有 LC-StudyLab（Chat / RAG / Workflow / Deep Research）
              +
核心方法：多粒度代码检索（HybridG + 反馈补检 + A3 重排）
              +
实验室 Java 后端代码仓与 LabCodeLoc 数据集
              +
LabDevRAG 研发文档知识库
              +
smartfarm-front-applets 小程序代码助手
              ↓
面向编程学习、代码理解与工程排查的检索增强智能体系统
```

### 1.1 个人工作边界表述

- LC-StudyLab 是本人基于 LangChain、LangGraph、FastAPI、FAISS、uni-app 等开源框架自主设计和实现的学习与研究 Agent 系统。
- 现有 Chat、RAG、学习工作流和深度研究能力保留并持续完善。
- 本阶段新增的核心工作是：Java 代码索引、HybridG/反馈/A3 代码定位服务、Code Locator Agent Tool、代码—文档协同工作流、小程序代码助手、私有数据集、系统级评测与反馈自适应。
- 开源框架是底层依赖；系统架构、功能实现、数据构建、实验和部署成果按实际贡献如实描述。

### 1.2 数据使用原则

- 纳入系统的实验室 Java 代码仓，统一用于索引、数据集构建和实验；不按最终用户角色做仓库可用性区分。
- 统一可用不等于无清洗：`.env`、密钥、令牌、证书、账号、生产连接串、依赖缓存、构建产物和二进制文件必须在索引/数据集构建前排除。
- 若调用外部 LLM，仅发送最小必要 query 与候选片段；按实验室统一策略配置并保留调用审计。

## 3. 开题阶段：应呈现什么

开题不是展示“所有功能做完”，而是证明问题重要、方案可行、已有基础扎实。

### 3.1 开题已具备/应核对的内容

- [ ] 研究题目统一为“检索增强代码学习/代码理解 Agent 系统”方向，题目与导师确认。
- [ ] 明确核心问题：通用文档 RAG 难以定位代码函数和文件；Agent 缺少真实代码证据；复杂问题需要代码与文档协同。
- [ ] 展示 LC-StudyLab 已有能力：Chat、文档 RAG、学习工作流、SSE、LangGraph 状态管理、小程序入口。
- [ ] 展示代码检索方法路线：BM25 + 函数 Dense + 文件 Dense + 图信号，反馈补检，A3 路由和重排。
- [ ] 展示 Java 后端仓库接入计划与 LabCodeLoc/LabDevRAG 数据构建方案。
- [ ] 展示可验证计划：方法层、私有仓层、系统层、反馈自适应层的四级评测。

- [ ] 增加或替换为“整体系统架构”页：LC-StudyLab、Code Locator、文档 RAG、小程序、Java 代码仓、数据集。

## 4. 中期阶段：应呈现什么

中期的关键是从“方案和原型”转变为“系统已跑通、核心结果可信”。

### 4.1 中期必须达到的技术检查点

- [ ] CodeSearchNet 和 SWE-bench Lite 主实验收口，结论与结果文件一致。
- [ ] 至少一个实验室 Java 后端仓完成符号、文件、向量和图索引构建。
- [ ] Code Locator v1 可通过 API 返回文件/类/方法、行号、片段、索引版本和检索诊断。
- [ ] Code Locator 可作为 Chat/代码学习 Agent 的工具调用。
- [ ] 小程序“代码助手”页 v1 可完成查询和查看候选，不要求完整反馈自适应。
- [ ] LabDevRAG 初版可用，至少有一组研发文档问答案例。
- [ ] LabCodeLoc 试验版有可审计的样本、标注格式和初步统计；若未达到正式规模，必须如实说明。

### 4.2 中期实验与案例

- [ ] 方法层：CSN、SWE-bench Lite、HybridG/反馈/A3 消融和时延成本。
- [ ] 私有仓试验：Java 仓的功能定位/缺陷定位小样本，对比 BM25、Dense 和完整方法。
- [ ] 系统案例：至少 3 个“代码定位 + 文档 RAG + Agent 解释”完整案例。
- [ ] 明确未完成项：正式私有数据集、全量系统人工评测、反馈自适应/RLHF，放入中期后计划。

### 4.3 中期 PPT 更新清单

源文件建议：`paper/代码检索-硕士学位论文中期报告.pptx`。

- [ ] 增加“开题计划与当前实际进度对照”页。
- [ ] 增加“代码检索从离线算法到 Code Locator 服务”的架构与 API 页。
- [ ] 增加“Java 仓索引与代码助手小程序”实机截图/接口结果页。
- [ ] 展示方法主结果和私有仓初步结果；严格注明样本量与任务口径。
- [ ] 增加系统端到端案例页：用户问题 → 代码候选 → 文档证据 → Agent 回答。
- [ ] 增加“现存问题与中期后计划”页：数据集扩大、对照实验、反馈自适应、性能/部署。
- [ ] 更新后导出 PDF，核对结果版本、图表来源、参考文献和页码。

**中期答辩最低演示：** 能从小程序或 Swagger 演示真实 Java 仓代码定位，并说明该结果如何被 Agent 用于解释；网络/模型不稳定时准备离线录屏或固定截图。
