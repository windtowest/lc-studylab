# 检索增强代码学习 Agent：实施任务清单

> 配套设计：[`design.md`](design.md)  
> 使用方式：严格按阶段顺序实施；每完成一项在 `[ ]` 中改为 `[x]`，将命令、结果、风险和产物路径记录到“完成记录”。  
> 原则：先完成可验证的代码检索方法与服务化，再做 Agent 协同、前端、私有数据集和反馈自适应。不要在实验未收口前直接开始 RL/RLHF。

## 0. 项目基线与决策冻结

- [ ] 0.1.2 检查并记录当前 CodeSearchNet、SWE-bench Lite、Dense embedding、文件索引和调用图资产是否存在且版本一致；缺失资产列入重建计划。
- [ ] 0.1.3 将所有现有实验结果按“历史结果 / 当前干净复跑结果 / 待复跑”分类，明确论文和系统展示只引用哪一版。
- [ ] 0.1.4 为 LC-StudyLab 后端和小程序分别建立可运行的开发环境与最小健康检查命令；不读取/提交任何真实 `.env`。
- [ ] 0.1.5 创建总实验日志模板：记录 commit、数据版本、配置、随机性、设备、耗时、模型、成本、失败原因。

**验收：** 新机器或新环境可按文档完成至少一个小样本检索评测、后端 `/health` 调用和小程序页面本地启动。

### 0.2 决策首批业务范围

- [ ] 0.2.1 确定首批实验室 Java 后端仓库；登记仓库名、Git 访问方式、分支/commit 策略、代码规模和是否允许向外部模型发送最小化片段。
- [ ] 0.2.2 冻结首版支持语言：Java 为主；`smartfarm-front-applets` 的 JavaScript/Vue 作为第二阶段跨语言补充；其他语言暂不承诺线上支持。
- [ ] 0.2.3 确定统一数据使用规则：纳入系统的实验室代码均可用于索引、数据集和实验；同时定义自动排除的敏感文件模式（`.env`、密钥、令牌、证书、生产连接串、依赖与构建目录）。
- [ ] 0.2.4 冻结首版任务类型：功能定位、缺陷/日志定位、代码学习路径、接口实现定位；不承诺自动提交补丁。
- [ ] 0.2.5 冻结首版上线边界：仅开发/实验室环境，索引构建由后端管理命令触发，代码助手对纳入的仓库统一可用。 

**验收：** 有一页仓库清单与统一数据使用规则，首版支持范围可明确写进论文和演示说明。

## 1. 收口代码检索方法与离线实验

### 1.1 完成核心方法实验

- [ ] 1.1.1 复核 CodeSearchNet Python 基线：BM25、Dense、HybridG，统一使用相同数据切分和指标实现。
- [ ] 1.1.2 完成/复跑 HybridG 的消融：去 BM25、去文件层、去图层、错误图融合方式与 post-fusion 对比。
- [ ] 1.1.3 完成 SWE-bench Lite 300 文件级定位实验，固定“至少一个 gold 文件命中”口径，并明确它不是自动修复率。
- [ ] 1.1.4 完成反馈补充检索实验：区分图扩展、查询重写、双支路；报告候选池覆盖和头部排序影响。
- [ ] 1.1.5 完成 A3/重排实验与 leave-one-out 消融；报告 R@K、MRR、端到端延迟、LLM 调用次数、成本和回退次数。
- [ ] 1.1.6 复核所有结论，移除任何未被当前大样本/干净复跑支持的 claim。

**验收：** 每项主结论有可执行命令、原始 JSON、图表脚本和复跑记录；论文/PPT只引用当前有效结果。

### 1.2 提炼可服务化的检索核心

- [ ] 1.2.1 从 `paper/paper/src/hybrid_retriever.py` 抽取无评测依赖的融合逻辑，定义输入/输出类型和单元测试。
- [ ] 1.2.2 将 BM25、函数 Dense、文件 Dense、图信号的运行时接口与离线评测数据结构解耦。
- [ ] 1.2.3 定义线上候选 ID：`repository_id / commit / path / qualified_name / kind / line span`；禁止使用评测行号作为业务 ID。
- [ ] 1.2.4 定义检索配置版本：融合权重、Top-K、图权重、阈值、embedding 模型、reranker 模型均可追踪。
- [ ] 1.2.5 编写小型 Java 冒烟仓库测试：给定 3–5 条问题，应稳定返回预期文件/类/方法；前端跨语言测试作为第二阶段补充。

**验收：** 不读取 CSN/SWE-bench 数据也能对本地小仓库执行 `query → hits`；融合层单元测试通过。

## 2. 构建真实仓库索引能力

### 2.1 新建代码检索服务模块

- [ ] 2.1.1 在 `agent/lc-studylab/backend/code_retrieval/` 建立模块骨架：schema、仓库注册、索引资产、查询服务、任务、反馈存储。
- [ ] 2.1.2 设计仓库注册表：仓库 ID、授权位置、语言、允许外发策略、当前可用索引版本、状态和创建者。
- [ ] 2.1.3 实现 Java 的符号抽取适配：包、类、接口、枚举、构造器、方法、注解和方法调用；验证路径、限定名和行号。
- [ ] 2.1.4 为 Java 首版实现文件层摘要：模块/包路径、类名、公开方法、必要注释和接口关系；记录摘要构建规则版本。
- [ ] 2.1.5 将 JavaScript/Vue 符号抽取列为第二阶段跨语言扩展，复用首版统一 schema；不阻塞 Java 主链路。
- [ ] 2.1.6 实现代码分块与片段截取：返回上下文前验证总长度、行号和敏感信息策略。
- [ ] 2.1.7 实现调用图/导入关系的首版构建；对无法可靠解析的动态调用标注不确定，不伪造边。
- [ ] 2.1.8 实现索引版本目录与原子切换：新索引校验成功后再替换“当前版本”，失败不影响旧版查询。

**验收：** 能为首批两个仓库生成可审计索引，输出文件/符号数、图规模、构建日志、commit 和索引版本。

### 2.2 检索运行时与 A3 接入

- [ ] 2.2.1 实现 BM25、函数向量、文件向量三通道并行查询与超时处理。
- [ ] 2.2.2 接入 HybridG：加权融合后图结构 post-fusion 加分；单元测试验证图层不引入候选池外候选。
- [ ] 2.2.3 接入反馈补检：将缺失分类、查询重写、图扩展做成可关闭的策略；记录每支路是否触发与增量候选数。
- [ ] 2.2.4 接入 A3：路由依据、阈值和行为配置化；响应中返回 route、耗时、LLM 调用数与回退信息。
- [ ] 2.2.5 接入 listwise reranker；强制 JSON 校验、超时、一次有限重试和基线排序回退；记录回退但不宣称绝对零退化。
- [ ] 2.2.6 增加内存索引缓存与仓库隔离；限制同时加载的仓库数量，避免多仓库耗尽 GPU/内存。
- [ ] 2.2.7 制定并实现外部 LLM 最小化发送策略：仅发送必要的 query/候选摘要或片段，按实验室统一策略配置并保留审计记录。

**验收：** `CodeLocator.query()` 对真实仓库返回 Top-K 文件/符号、片段、索引版本、路由和完整诊断；错误配置、模型不可用、索引不存在均有可读错误。

## 7. 反馈驱动自适应（最后实施）

### 7.1 建立可审计反馈闭环

- [ ] 7.1.1 明确仅收集显式用户反馈：有用/无用、目标候选、可选原因；提示用户不要输入密钥或敏感内容。
- [ ] 7.1.2 为每条反馈保存 query、候选排名、索引版本、配置版本、时间、匿名会话标识和反馈类型。
- [ ] 7.1.3 建立人工审查/去噪规则，防止误点击、恶意反馈和过期索引反馈直接进入训练。
- [ ] 7.1.4 冻结一份反馈前的 holdout 测试集，禁止其参与参数优化。

### 7.2 首版自适应策略：离线参数优化

- [ ] 7.2.1 先实现低风险方案：根据开发集和清洗后的反馈，优化融合权重、A3 阈值或 reranker 选择策略。
- [ ] 7.2.2 比较初始配置与反馈调优配置，分别在固定 holdout 和新反馈任务上评测。
- [ ] 7.2.3 对每次策略升级生成版本、变更说明、离线对比和回滚方案；只允许人工审批后发布。
- [ ] 7.2.4 若效果不稳定，保留为负面结果；不要为了“自进化”叙事自动上线退化配置。

### 7.3 可选扩展：偏好重排/自我评审

- [ ] 7.3.1 将现有 `SelfRewardAgent` 用于离线候选回答评审，不让其自行覆盖用户反馈或真实标注。
- [ ] 7.3.2 使用 `rlhf_integration` 生成偏好对，先验证数据量、噪声和隐私合规，再决定是否训练轻量 reranker。
- [ ] 7.3.3 将训练环境与在线推理环境隔离；训练依赖（Ray/DeepSpeed/vLLM 等）不得污染稳定服务环境。

**验收：** 至少完成“反馈 → 清洗 → 离线调优 → 固定测试集验证 → 人工发布”的完整闭环；RL/RLHF 未完成不阻塞主系统和论文。
